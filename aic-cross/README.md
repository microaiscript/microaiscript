# aic-cross

`aic-cross` compiles AiScript source (`.ais`) to portable bytecode (`.aic`), in the
spirit of MicroPython's `mpy-cross`. The bytecode is executed by the stack VM in
`src/vm.c`, driven by the `ais-vm` runner.

The bytecode path is experimental. The tree-walking interpreter (`bin/aiscript`)
is the reference implementation of the language; the VM is checked against it by
the dual-path conformance suite (`make test_conformance`) and is known to differ
in some corners (for example string quoting when printing). `bin/aiscript` cannot
run `.aic` files.

## Build

`aic-cross` links against the object files of the main build, so build the
project first:

```bash
make            # from the repository root
make -C aic-cross
```

This produces `aic-cross/aic-cross`.

## Usage

```
aic-cross [options] <input.ais>

  -o <file>      Output file (default: input.aic next to the input)
  -O<level>      Optimization level 0, 1 (default) or 2
  -g             Include debug information (line numbers)
  -march=<arch>  Target architecture label (esp32, arm, x86_64); recorded and
                 printed in verbose mode, it does not change code generation
  -v, --verbose  Print compilation details
  -d             Disassemble the generated bytecode
  -h, --help     Show help
  --version      Show version
```

Compile and run:

```bash
aic-cross/aic-cross -O2 examples/fizzbuzz.ais     # writes examples/fizzbuzz.aic
bin/ais-vm examples/fizzbuzz.aic                   # build it with: make vm
```

### Exit codes

| Code | Meaning |
|------|---------|
| 0 | Success |
| 1 | Invalid command line |
| 2 | Cannot read the input or write the output |
| 3 | Syntax error in the source |
| 4 | Compilation error |

## Optimization levels

- `-O0`: no optimization.
- `-O1`: removes unreachable code after `RETURN`/`HALT`.
- `-O2`: additionally runs peephole and jump-threading passes.

Constant folding, inlining and constant propagation are declared in
`optimizer.c` but not implemented yet. Run `aic-cross -v -d` on a script to see
what a level produced.

## Bytecode format

The file starts with the magic `AICC` and a version (currently 1.0), followed by
the code, constant pool, symbol table and optional debug sections. The reader and
writer are in `src/bytecode_io.c`; opcodes and structures are declared in
`include/bytecode.h`.

## Embedded targets

To embed a program in firmware, convert the bytecode to a C array and load it
with the functions in `include/bytecode.h`:

```bash
aic-cross/aic-cross -O2 firmware.ais
xxd -i firmware.aic > firmware_aic.h
```

The VM's host bindings (`as_vm_bind_host_ffi` in `src/vm.c`) include `peek` and
`poke`, which read and write raw memory addresses for microcontroller work. They
are bound only for bytecode programs run through the VM and give a script full
control of the process, so do not run untrusted bytecode with them available.

## Source layout

| File | Purpose |
|------|---------|
| `main.c` | Command-line driver |
| `compiler.c` | AST to bytecode compiler (`as_compile`, declared in `include/compiler.h`) |
| `optimizer.c` | Optimization passes |
| `Makefile` | Build rules |
